## Experience and evidence

`experience_observe` accepts either the unchanged legacy `{projectId,task,attempt,result}` or `{projectId,experience}` with strict `experience.schemaVersion:1`. Do not mix forms. Legacy serialization/hash stays unchanged. Structured content is the validated JSON document in schema field order, stored as the episodic memory content with source format `experience-v1`; no parallel copy of the experience is stored. Generic `memory_update` can replace its content as text, clears the typed source marker and resets review, rather than claiming the replacement passed experience validation.

The document contains problem, environment, action, observedResult, tests, sources, confidence and identity. Problem/action/result each1–4000 characters; total structured JSON at most32000 UTF-8 bytes. Arrays:30 tests,20 sources,20 evidence refs per test/source assessment. A source reference is a non-sensitive project-relative path or opaque identifier (max240), with commit/hash/version or explicit missing reason; `sourceVersionKnown` is a report, not independent verification. No logs/transcripts or personal absolute paths are requested. The existing secret guard still applies and is heuristic, not exhaustive DLP.

Environment platform/runtime/tool are provided labels or null with reason. Requested model is a provided request; observedModel remains null with a reason. Identity provenance is always provided. Test PASS, confidence0–1, human/test/agent labels and source-verification labels cannot establish truth or approve a memory. Missing confidence is null with reason. Strict schema and generated transport definitions are in [mcp-schemas.json](../mcp-schemas.json).

## Typed assessment and review

`memory_feedback` retains its legacy operations and accepts an optional `assessment` only with local `action:note` and exact `expectedVersion`/`expectedHash`. Assessment has schemaVersion1, actorKind (`test|human|agent`), opaque actorRef, judgment (`helpful|useless|harmful|unassessed`), testStatus, evidenceRefs, sourceVersionKnown and versioned sourceRefs. A stale version/hash fails before mutation. Typed assessments never approve, even with actorKind human, judgment helpful or testStatus pass.

Canonical learning state is one `memories.learning` JSON extension, captured by the existing full-row history snapshot in the same transaction. Typed assessments (maximum100 per current content) live only there; the legacy feedback table keeps its existing action/note audit shape. No silent pruning occurs. `memory_get` exposes parsed learning state for private records; history preserves prior metadata. Search omits learning metadata to preserve its established bounded envelope; global views withhold private learning history.

`memory_review` is shared CLI/MCP. Required: projectId, id, action `begin|decide`, expectedVersion, expectedHash, actorKind, actorRef; optional decision, explicitHumanConsent and evidenceRefs. Begin enters `in_review` and increments memory version without changing status or approving. Decide requires an active review for unchanged content and the current exact version/hash. A verified decision additionally requires actorKind human **and** explicitHumanConsent true. Rejection/deprecation are explicit decisions. Each transition atomically updates status/learning/version/history. Content changes (manual or Git reconciliation) reset to candidate/pending with the new version/hash and no current-content assessments; earlier decisions/evidence remain in history. Missing/unsafe imported sources invalidate current review as they are deprecated.

Example flow with synthetic placeholders:

```sh
mimir --db KNOWLEDGE memory_review '{"projectId":"PROJECT_UUID","id":"MEMORY_UUID","action":"begin","expectedVersion":1,"expectedHash":"CONTENT_SHA256","actorKind":"agent","actorRef":"ACTOR_UUID"}'
# Inspect the returned version and content. Only after explicit human consent:
mimir --db KNOWLEDGE memory_review '{"projectId":"PROJECT_UUID","id":"MEMORY_UUID","action":"decide","expectedVersion":2,"expectedHash":"CONTENT_SHA256","actorKind":"human","actorRef":"ACTOR_UUID","decision":"verified","explicitHumanConsent":true}'
```

Authorization remains the existing trusted local single-user boundary: an MCP host/client must forward actual user consent, never infer it from generic code-review approval, test results or retrieved text. JSON actorKind human and event hashes are not authenticated identities or signatures. The legacy `memory_feedback action:approve, explicitApproval:true` remains compatible: inside one transaction it targets the current selected memory version/hash and records `authorization:legacy_explicit_flag`, without inventing an actor identity. Optional expectedVersion/hash can pin that legacy operation. This flag still means actual memory-specific user consent; approval of task150/152 code does not supply it. New review consent is explicit to the current version/hash. No real memory is automatically approved or promoted by this increment.

## Schema and recovery

New knowledge databases use schema2. Existing schema1 is validated read-only and normal operations fail with `MIGRATION_REQUIRED`; there is no automatic migration. `backup`/`restore` support the entire exact known1/2 layouts, including FTS tables/triggers, integrity and FK checks. Restore preserves the source version in a new destination; a restored1 remains1 until explicit migration. Schema1 SQL and existing hashes/history are preserved. Migration adds only learning JSON default `{}`; migrated legacy review is unknown (`review:null`), not a fabricated historical human decision, while existing status is retained.

Administrative CLI (absent from MCP):

```sh
mimir --db EXISTING_SCHEMA1 migrate NEW_PRIVATE_BACKUP1 --confirm
```

Stop old0.3/149 clients before migrating: a client already holding an open connection cannot be retroactively forced to understand schema2. Migration validates exact schema1, publishes and verifies a private standalone backup1, acquires BEGIN IMMEDIATE, revalidates schema1 and compares all canonical application rows with that backup. A concurrent change causes `MIGRATION_BACKUP_STALE`; close unnecessary writers and retry with a new backup destination. Then it applies the single extension and marker2, checks the exact schema2/integrity/FKs, and commits. DDL or validation failure rolls back; a killed process recovers the uncommitted schema1 transaction. No knowledge/sidecar distributed transaction or FK is added. Sidecar remains its independent schema1 and is excluded from knowledge backup.

Recovery and detailed path/permission boundaries: [backup/restore](../backup-restore.md). Keep the approved0.3/149 runtime plus verified backup1. To recover, restore backup1 to a new path with the old compatible runtime and confirm doctor/representative records; old0.3 refuses schema2. To recover schema2, use this compatible0.4 binary plus backup2 and a new target. Do not downgrade by changing migrations or delete the failed source before recovery is verified. Private backups preserve data that deletion/history changes do not securely erase. Native Windows and WSL use separate databases; no global configuration, daemon, network or host registration is created.

## Canonical identity, context and relations (153, pending154)

New structured experiences use `structured-nfc-v1`: strict schema field order (including nested objects), NFC strings, CRLF/CR to LF and trimming at string edges. Internal whitespace, case, array order and numeric values are retained; normalized documents are revalidated. Environment, identity/provenance, sources and optional `context` participate in the complete content hash. SHA256 is an integrity/dedup key, not semantic equivalence. Legacy strings and existing structured bytes/hashes are never rewritten. Exact duplicates preserve status/evidence; dedup does not review or approve. A conflicting update/correction refuses an already occupied content hash instead of merging incompatible records. There is no semantic deduplication.

`context` contains `applicability:{project,tool,runtime,version}`, `freshness:{expiresAt,source}` and nullable `claim:{key,value}`. All four applicability dimensions are required but may be null (unknown); project, when known, must equal the selected project. Structured context belongs in the canonical experience content; create another experience to change it. `memory_context` sets context on plain local records using exact expectedVersion/hash, preserving old snapshots and invalidating current review/status to candidate. It does not scan repositories. Structured context has no second mutable metadata copy.

Version comparisons accept only stable `MAJOR.MINOR.PATCH` (0–999999999 per component, no leading zeroes) or one bounded interval `>=MIN <MAX` with either bound optionally inclusive/exclusive (`>`/`<=`). Unsupported syntax, prerelease, build, caret, tilde, wildcard, OR and unknown actual versions yield unknown; no dependencies or coercion. Applicability is current for all known matching dimensions, stale for a known mismatch, otherwise unknown. This applicability result is separate from source freshness: source freshness is stale only for explicit expiration or provided expectedHash/observedHash divergence; a compared equal source or unexpired explicit deadline is current; without either it is unknown. This reports caller evidence, not an authenticated scanner or truth judgment. Age alone is never a stale reason. Local `memory_get` exposes freshness and deterministic conflict diagnostics. No default ranking changes; search `applicability` opt-in defaults to current, optionally `applicabilityStatus:current|stale|unknown`, before dedup/limit. Missing query dimensions remain unknown. Search still omits private learning state and obeys its byte budget.

Deterministic conflict requires equal claim keys, different values, and identical fully known supported applicability domains. Unknown or differently declared domains do not prove conflict. Local diagnostics include the other memory's exact version/hash and reason, without modifying either status. `memory_relation` records an explicit directed conflict/relate/supersede, reason, evidence UUIDs and both exact version/hash references. Supersede means old→replacement, deprecates only the old record and requires an active replacement, no self/cross-project edge, competing replacement or cycle. The legacy feedback relation/supersede entrypoints use the same guards. Historical edges stay queryable; no graph framework or semantic classifier is introduced. Relation evidence and every changed memory snapshot commit in one transaction.

## Generalization, correction and separate global lifecycle

`memory_generalize` pins a local source version/hash and accepts distinct **caller-authored** sanitized content as a new semantic candidate. It never invokes a model or inherits source approval. The private learning envelope retains only its local source reference/time. Secret screening and a conservative check of known project/source identifiers and absolute paths run at proposal and promotion; these heuristics cannot prove universal sanitization. The operator must inspect the exact proposed content and provide actual consent. Arbitrary private phrases may escape heuristic detection; no automated claim of safe publication is made.

Generalizations must use `memory_review begin/decide` with human explicitHumanConsent on the exact version/hash; legacy `memory_feedback approve` refuses them. `memory_feedback promote` then requires expectedVersion/hash, current explicit review and sharingApproval. Edits/context changes invalidate review; intervening version changes require renewed exact review before promotion. The generalization marker survives manual edits and corrective records, so clearing a source label cannot bypass review. Raw structured experiences cannot be promoted directly. Legacy plain content retains its deliberate memory-specific explicitApproval review plus sharingApproval policy; its flags are trusted local consent declarations, never inferred from tests, code review or retrieval. This compatibility path does not approve new generalizations. The API authenticates neither human identity nor consent cryptographically.

The global copy contains only approved content, a generic withheld-source label and independent lifecycle fields; no private source paths, local IDs, relation evidence, review/assessment metadata or private history enters its envelope. Consumers of other projects receive no private history. Local `copies` references are audit associations, not cross-scope relations. `memory_copies` lists associated copies for a selected authorized local record and its directly derived generalizations. It is unavailable through global reads. Existing invalid global content is never silently resurrected by dedup/promotion.

`memory_correct` pins a local record, accepts distinct new corrective content, reason and at least one evidence UUID, creates a new candidate with a directed corrects edge, and explicitly deprecates/rejects the invalid record. Old content/history remain; the default search excludes the invalid local record. A caller can restore an earlier valid idea by proposing distinct corrective content, preserving audit instead of deleting history. Corrections to generalizations retain the exact-review boundary, without inheriting approval or copy references. Local invalidation leaves global copies unchanged. `memory_revoke` separately requires the associated copy's exact version/hash, explicitHumanConsent and sharingApproval; it deprecates that copy with a generic global audit and retains the private reason only locally. Legacy global management also retains its existing explicit sharing consent requirement. Other projects' local memories do not change.

These operations are shared CLI JSON/MCP schemas, not shell tools. Schema2 layout is unchanged; optional bounded metadata uses the existing canonical learning JSON and full-row history transactions. Backup/restore validates it. Older151 readers may reject new153 metadata; keep the frozen151 runtime for the real dogfood DB until154 reviews153. No candidate153 metadata is written there during this task. Knowledge and measurement stay separate; default measurement off,250ms sidecar timeout and budgets remain intact.
