# Disposable host acceptance procedure

This is a procedure, not evidence that Codex or Antigravity passed. Doctor can report the installed engine/runtime, executable, platform, Git, database path, schema, SQLite/WAL/FTS and SDK. It cannot inspect host settings or prove host consent semantics.

1. Complete local build/checks with the supported native Node runtime. Record `node --version`, `git --version`, the absolute Node executable and `dist/cli/index.js` paths.
2. Create a disposable empty Git repository outside the private database directory. Use only synthetic text, for example `architecture.md` containing `fixture renderer queue`. Never use a real workload without explicit authorization.
3. Create a new private database: `node /absolute/MimirNL/dist/cli/index.js --db /private/temp/host.sqlite init`. Run `doctor` through the identical executable and DB path.
4. Consult the installed client's current `--help` and documented MCP settings. Configure an isolated profile or per-process MCP override, if supported, with command = that absolute native Node, arguments = absolute CLI path, `--db`, disposable database path, `mcp`, `stdio`. Do not modify global user configuration. If the host cannot isolate settings, coordinate explicitly with the operator before proceeding.
5. In the actual host, initialize and list tools; register the synthetic repository with explicit ingestion authorization. Store, search, get and add feedback to fixture data. Verify returned project IDs, source trust labeling and errors for invalid IDs and missing confirmation. Verify the host obtains an actual human decision before forwarding approval/sharing/deletion flags. SDK tests alone cannot establish this behavior.
6. Restart the host session with the same explicit database, retrieve the stored memory, then test the second host sequentially on the same native-runtime database. Do not cross Windows/WSL live WAL access.
7. Record client version, isolated settings, exact operations, sanitized responses, approval behavior and failures. Keep stdout exclusively JSON-RPC; SQLite runtime warnings may appear on stderr. Afterward close all clients and delete only these disposable fixtures/data.

For missing Git, install it separately; doctor reports unavailable rather than downloading anything. `UNSUPPORTED_SQLITE` requires a patched Node runtime before database creation; `UNSUPPORTED_SCHEMA` requires the compatible engine or a pre-upgrade restore. `UNSAFE_GIT` indicates unsupported metadata/configuration; do not disable the guard. `TARGET_EXISTS` requires another fresh recovery path. A green doctor is local engine health, not host acceptance.
